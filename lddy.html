生产线 → 单台扫码报工
报工系统 → MES 入库 → ERP 集成
报总装账务 → WMS 入库扫描
同步质控状态
🕓 定时任务同步，入库后持续更新
+
下交付单 + 绑定周转卡
可在扫码入库前或后操作
↓
WMS 入库记账（总装 → 成品）
必须绑定交付单+周转卡，否则 ERP 记账不成功
自动 人工操作 系统操作
⚠ 记账前置条件：总装需下交付单并绑定周转卡，绑定后成品报账到 ERP 才能成功。
🕓 质控状态：质控状态通过定时任务与入库扫描同步，入库后仍会持续更新。
📋 交付单时机：下交付单+绑定周转卡可在 WMS 扫码入库前或扫码入库后操作，但必须在入库记账前完成。

3.2 成品发货流程

CRM 导出发货计划 → 邮件发备货计划 → 打印备货计划
线下按计划备货 → ERP 开单 → 自研批量打单系统
关联 ERP 订单打印发货单 → PDA 按订单扫描装车 → 条码绑定 → WMS 确认出库 → ERP 手工确认
自动 人工操作 系统操作

⚠ 关键信息：备货在 ERP 开单之前，通过邮件线下传递备货计划并打印备货；ERP 开单后，再按实际订单 PDA 扫描装车。出库通过 ERP 中间表集成，PDA 扫描后需人工到 WMS 确认数量并扣减库存，再由 ERP 手工确认出库数量完成账务。每天日结，只做当天发货计划。允许甩货出库。

3.3 成品领料流程

BPM(OA) 提交审批 → 审批通过
自动同步明细到 WMS → 仓库确认退货 → 仓库签收
自动扣减库存 → BPM 签审 → 手工推送 ERP
自动 人工操作 系统操作
✅ OA 与 BPM 为同一套系统。审批通过后自动同步领料明细至 WMS，仓库签收后自动扣减库存；BPM 签审完成后仍需手工推送 ERP 完成账务。

3.4 质量管理流程

入库前 QMS 外检结果自动同步质控合格状态到 WMS
入库后 发现问题使用 WMS"封存"功能，封存状态不可发货
解封 需走流程后在 WMS 操作"解封"

业务痛点（已确认）
P1 · 高
发货计划频繁变更，无系统订单支撑
发货计划全靠手工整理，CRM 导出后邮件发给物流部。计划发货前后都在变化，变更时无法实时同步，导致仓库备货白做或遗漏。
经营部物流部仓库
P2 · 高
线下邮件沟通，信息传递链路长
CRM 导出 → 邮件 → ERP 开单 → 仓库备货，至少 3 个手工环节，响应慢、易出错。
多部门协同
P3 · 高
物流履约无系统，在途到签收无法跟踪
出库后在途状态、运输进度、客户签收完全靠人工电话/微信跟踪，无 TMS 系统。
客户满意度
P4 · 中
成品领料 ERP 推送仍需手工
OA 审批通过后自动同步领料明细至 WMS，仓库签收自动扣减库存；但 BPM 签审完成后仍需手工推送 ERP，账务与仓库未全链路打通。
最后一环手工
P5 · 中
出库账务手工两步确认
WMS 确认数量 + ERP 手工确认，两次手工操作，效率低且存在数据不一致风险。
数据风险
P6 · 中
ERP 中间表无防错，条码重复需人工修正
WMS 与 ERP 通过中间表集成，但中间表无防错校验机制。记账时条码重复会导致失败，需人工逐条修改才能完成记账。
集成缺陷
P7 · 高
返包更换条码，无法追溯原始记录
返包（更换周转卡/包装）时重新绑定新条码，原始条码丢失，无法追溯该物料的生产来源、质控记录等历史信息。
追溯断裂
P8 · 中
质控状态滞后影响备货计划
质控部合格/不合格判定结果同步到 WMS 存在滞后，导致仓库按备货计划拣货时才发现物料被"封存"，备货计划被打乱，需重新调整。
封存滞后
P9 · 高
库存寻源纯手工，效率低
查找物料库存位置、可用量等信息完全依赖人工查询，无系统自动寻源能力，导致备货、拣货耗时长，容易出错。
人工查询

决策分析

调研结论

凌达自研 WMS 在仓库作业层面完全可用，入库、出库、库存管理等核心功能运转正常。核心短板在于发货无准确的系统订单计划，计划在发货前后频繁变更。目前方案 A/B 的具体改造范围、接口对接量尚未完全评估清晰，暂不做定论，下一步先让业务侧试用验证。

核心问题

发货无准确的系统发货计划下发，计划在发货前后频繁变更
1 没有系统化的发货计划，全靠 CRM 导出 → 邮件 → ERP 手工链路
2 发货前计划变更 → 仓库已备货需重新调整，备货白做
3 发货后计划变更 → 甩货出库、补发货等异常操作增加
4 变更无法实时同步到仓库 → 信息滞后导致发错货、漏发货
待评估

改造方向自研 WMS 补订单模块 + 新建 TMS
对接接口待评估
作业影响不影响现有成熟作业
待评估

改造方向替换自研 WMS + 新建 TMS
对接接口待评估（涉及系统较多）
作业影响全部切换 WMS PDA
